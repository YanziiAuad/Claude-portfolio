# Glossary (in plain English)

Words we've run into, explained simply. We'll keep adding to this as we go.

## The basics

**Code** — Written instructions for a computer. Like a recipe: the computer follows the steps exactly as written.

**Website vs. web app** — A website mostly shows information (like a poster or a brochure). A web app lets you *do* things: sign in, save stuff, buy things (like a vending machine instead of a poster).

**Frontend** — The part of an app you see and click: buttons, text, colors. The dining room of a restaurant.

**Backend** — The behind-the-scenes part that stores data and does the work. The kitchen of the restaurant.

**Database** — Where an app keeps its information. A giant filing cabinet: each *table* is a drawer, each *row* is one folder in that drawer.

**API** — The way two programs talk to each other. Like a waiter: you tell the waiter what you want, the waiter tells the kitchen, and brings your food back.

**API key** — A secret password that lets your app use a service (like Supabase or Stripe). Like a house key: whoever has it can get in, so never share it or put it in public code.

**Environment variables (`.env` file)** — A private list where we keep secrets like API keys, separate from the main code. Like a locked drawer next to your desk.

**Framework** — A ready-made starting kit for building apps, so you don't start from zero. Like buying a house frame and then choosing the paint and furniture.

## Our tools

**Git** — A program that tracks every change to your code. Like a video game's save points: you can always go back to an earlier save.

**GitHub** — A website that stores your Git projects online. Like Google Drive for code, with every save point kept.

**Repository (repo)** — One project folder on GitHub, with all its history. Like a binder for one school subject.

**Commit** — Saving a snapshot of your changes with a short note about what you did. A save point with a label.

**Push** — Sending your commits up to GitHub. Like uploading your saved game to the cloud.

**Branch** — A separate copy of the code where you can try things without messing up the main version. Like making a photocopy of your homework to experiment on.

**Pull request (PR)** — Asking to merge changes from a branch into the main version. Like handing your edited photocopy to the teacher and saying "can we use this version?"

**Supabase** — A service that gives your app a database, user logins, and file storage. The back office: filing cabinet, security desk, and storage closet in one.

**Vercel** — A service that puts your website on the internet so anyone can visit it. The landlord that rents your site a spot online. Every time you push to GitHub, Vercel automatically puts the new version up.

**Deploy** — Putting a new version of your site online for real. Like opening the doors of the store after rearranging the shelves.

## Coming later

**Resend** — Sends emails from your app (welcome emails, password resets, receipts). The app's mail carrier.

**Stripe** — Handles payments safely. The cash register, so you never have to touch anyone's card number yourself.
